    SmartOps Portal is a self-service website that lets you manage cloud resources and deploy applications without needing to be a technical expert.

    Think of it like this: Instead of filing a ticket and waiting for an engineer, you can describe what you need in everyday language — and the portal helps you do it step by step.

    What you can do here

    • Ask for changes — e.g. "add more capacity" or "create a storage bucket" using the Chat assistant
    • See your resources — view servers, storage, and other cloud items on the Dashboard
    • Deploy applications — upload a website, code folder, or app image via Services
    • Track deployments — check status, rerun, or remove apps under Deployments
    • Review activity — see who did what in Log History

    You do not need to know programming, AWS, or command-line tools. Follow the steps in this guide and use the on-screen buttons.

    You cannot use the portal until an administrator approves your account. This keeps the system secure.

    1
    Open the portal website

    Go to the URL your team gave you (usually something like http://localhost:5000 in testing).

    2
    Click "Request access"

    On the sign-in page, click the link below the Sign In button — not everyone has an account yet.

    3
    Fill in your details

    Choose a username (letters, numbers, underscore only), your work email, and a password (at least 8 characters). Type the password twice to confirm.

    4
    Wait for approval

    You'll see a success message. An admin must approve you before you can sign in. Contact your team lead if you wait more than 1–2 business days.

    5
    Sign in

    Once approved, return to the portal, enter your username and password, and click Sign In.

    Can't sign in?
    • "Pending admin approval" — wait for an admin to approve you
    • "Request was rejected" — contact your administrator
    • "Invalid username or password" — check spelling and caps lock

    This guide walks you through deploying to Amazon Web Services (AWS) using SmartOps Portal — from first-time setup to going live.

    Before you start — prerequisites

    • An AWS account with permission to create resources (EC2, S3, ECS, etc.)
    • AWS credentials configured on the server running SmartOps Portal (ask your admin)
    • A SmartOps Portal account approved by an administrator
    • For app deployments: your files ready (website folder or code ZIP)
    Admin setup (one time): On the server, run aws configure and enter your Access Key ID, Secret Access Key, and default region (e.g. eu-west-1). Then start the portal with start.bat or python backend-api.py.

    Path A — Deploy infrastructure with Chat (Provisioner)

    Use this when you need servers, networks, storage, or scaling — described in plain language.

    1
    Sign in and open Chat from the left menu.
    2
    Select Service & Account — e.g. VPC, EC2, Production account. Pick the correct AWS region from the region dropdown.
    3
    Describe your change — e.g. "create vpc" or "scale EC2 to 2 replicas". The assistant generates a plan.
    4
    Review YAML diff — compare before/after. Click Confirm if correct, or Reject to cancel.
    5
    Review Terraform plan — check what will be created, changed, or destroyed.
    6
    Approve the Pull Request — click Approve until status shows APPROVED (required before apply).
    7
    Apply Changes — click the green Apply button. Wait for "Apply complete!" confirmation.
    8
    Verify — check Log History for your workflow entries and Dashboard for new resources.

    Path B — Create AWS resources directly (Dashboard)

    Use this for one-off resources without the chat workflow.

    1. Open Dashboard from the left menu
    2. Find the resource card (EC2, S3, DynamoDB, Load Balancer, etc.)
    3. Click Create or Launch
    4. Fill in all fields marked with * — the form validates names, formats, and required values
    5. Submit and wait for the success message
    6. Refresh the list to see your new resource

    Path C — Deploy an application (Services)

    Choose the option that matches what you have:

    🌐 Static Website → AWS S3 + CloudFront

    1. Prepare a folder with index.html plus CSS/JS/images
    2. Open Services → Deploy Website
    3. Enter app name (lowercase, hyphens) and domain (e.g. app.example.com)
    4. Select your website folder and submit
    5. Portal uploads to S3, enables hosting, and optionally CloudFront CDN

    📦 Code ZIP → Docker → ECS

    1. ZIP your project (Python, Node.js, Go, Java, or static HTML)
    2. Open Services → Upload & Deploy
    3. Enter app name, container port (default 8080), upload ZIP
    4. Portal builds Docker image, pushes to ECR, deploys to ECS

    After deployment — verify & manage

    • Manage Deployments — see status, URL, rerun, edit, or destroy
    • Log History — filter by "Infrastructure workflow" or "Deployments"
    • Dashboard — confirm EC2, S3, ALB, and other AWS resources exist
    Validation tips: App names must be lowercase with hyphens (3–63 chars). Domains must look like app.example.com. Container ports must be 1–65535. Website uploads need index.html. If a field is wrong, you'll see a clear error message before anything is sent to AWS.
    Costs: AWS charges for running resources. Always confirm with your team before deploying to production accounts.

    The Chat section helps you request changes to cloud infrastructure by typing what you want — like messaging a helpful colleague.

    Step-by-step

    1
    Pick Service and Account

    At the top, choose what type of resource (e.g. EC2, S3) and which environment (e.g. production, development). If unsure, ask your team which account to use.

    2
    Describe your request

    Type in normal sentences. Examples: "Scale to 2 replicas", "Create a new storage bucket with encryption", "Add monitoring tags". You can also click the colored Quick action chips for common tasks.

    3
    Review the proposed changes

    The portal shows a before and after comparison. Read it carefully — green usually means "adding", red may mean "removing". Click Confirm if it looks right, or Reject to cancel.

    4
    Review the plan & apply

    You'll see a detailed plan of what will happen. If everything looks good, approve any required review step, then click Apply Changes to make it live.

    Tip: Be specific. Instead of "fix the server", try "Increase the server size to handle more traffic in production."

    The Dashboard is your control panel for viewing and creating cloud resources — virtual servers, storage, databases, load balancers, and more.

    What you'll see

    • Lists of existing resources (instances, buckets, tables, etc.)
    • Create or Launch buttons to add new resources
    • Forms that ask for names and basic settings — fill required fields marked with *

    How to create something new

    1. Open Dashboard from the left menu
    2. Find the resource type you need (e.g. "EC2 Instance", "S3 Bucket")
    3. Click the create button and fill in the form
    4. Submit — you'll get a success or error message at the top of the screen
    Important: Creating resources may incur cloud costs. When in doubt, confirm with your team before creating production resources.

    The Services section is where you publish apps and websites to the cloud. Pick the option that matches what you have:

    🌐 Static Website

    Best for: HTML/CSS/JS sites, landing pages, simple front-end files.

    You need: A folder of website files (not a ZIP of source code with a build step).

    Steps: Click "Deploy Website" → choose your folder → enter app name and optional domain → submit.

    📁 Upload Code & Deploy

    Best for: Python, Node.js, Go, or Java projects packaged as a ZIP file.

    You need: Your project in a .zip file. The portal builds a container automatically.

    Steps: Click "Upload & Deploy" → enter app name → upload ZIP → submit.

    Not sure which to pick? Simple website → Static Website. Python/Node/Java project → Upload Code & Deploy.

    After you deploy an app, it appears in the Deployments table with name, type, status, URL, and last updated time.

    Understanding status badges

    • APPLIED — Deployment succeeded; your app is running
    • ERROR — Something failed; click ▸ on the row to see details

    What the action buttons do

    ButtonWhen to use it
    ↻ RerunRun the same deployment again
    ✏️ EditChange name, port, or platform, then redeploy
    ✕ DestroyPermanently remove the deployment

    Click the ▸ arrow on any row to expand ID, created date, and extra details. Use search and filters at the top to find deployments quickly.

    Log History records important actions: sign-ins, deployments, approvals, and changes. Useful for auditing and troubleshooting.

    • Search — type a username, action, or keyword to filter
    • Level filter — show only warnings or errors if needed
    • Export — download logs as a spreadsheet (CSV) for reporting

    Regular users typically see their own activity. Administrators may see all users' logs.

    If your role is admin, you have extra responsibilities:

    Approving new users

    1. Click Users in the left menu (a red badge shows pending count)
    2. Review each request — check username and email look legitimate
    3. Click ✓ Approve to grant access, or ✕ Reject to deny

    Approved users can sign in immediately. Rejected users must contact you if they believe it was a mistake.

    Other admin capabilities

    • View all audit logs (not just your own)
    • Full access to all portal features

    Quick definitions of terms you may see in the portal:

    Cloud / AWS
    Remote computers and storage run by Amazon (or similar providers). You use them over the internet instead of owning physical servers.
    Deploy
    Publish or launch your application so it runs and can be accessed by users.
    EC2
    A virtual server in the cloud — like a computer in a data center you rent by the hour.
    S3
    Cloud storage for files — good for websites, backups, and documents.
    Docker / Container
    A packaged way to run an application with everything it needs bundled together.
    Deployment
    One recorded attempt to publish your app. You can rerun or delete deployments from the Deployments page.
    Environment / Account
    A separate space for resources — often "development" (for testing) vs "production" (for real users).
    YAML / Plan
    Technical descriptions of proposed changes. Review the summary; you don't need to edit these files yourself.
    Pull Request (PR)
    A review step where changes are checked before going live — like asking a colleague to approve before publishing.
    Region
    Geographic location of cloud data centers (e.g. US, Europe). Pick the one your organization uses.
    Q: I submitted a signup request but can't log in.

    A: Your account is waiting for admin approval. Contact your team lead or IT administrator.

    Q: The page says "API Offline".

    A: The backend server may not be running. Contact your administrator or restart the portal using the start script your team provided.

    Q: My deployment shows ERROR.

    A: Click ▸ on the row to expand details and read the error message. Common fixes: wrong file type, missing files in ZIP, or invalid app name.

    Q: I don't know which Service or Account to pick in Chat.

    A: Ask your team or manager. Using the wrong environment can affect live systems.

    Q: How do I change the screen theme?

    A: Use the dropdown in the top-right corner — Dark, Light, or Ocean. Your choice is saved automatically.

    Q: How do I sign out?

    A: Click the power button (⏻) next to your name at the bottom of the left menu.

    Q: Who do I contact for help?

    A: Reach out to your portal administrator or internal IT support team. Share screenshots and the error message you see.
