AWS Accounts

Connect one or many AWS accounts. The hub account assumes a cross-account IAM role in each target account, so the portal never stores long-lived keys. Switch the active account from the header.

How multi-account connection works

Hub account (portal) sts:AssumeRole Target account role Temporary credentials
  1. The portal runs in a hub account and uses its own IAM instance role (or an SSO role) as the base identity.
  2. Each target account has an IAM role (for example FDENexusCrossAccountRole) whose trust policy allows the hub account to assume it, ideally with an external ID.
  3. When you select an account, the portal calls sts:AssumeRole and receives short-lived credentials for that account.
  4. All subsequent API calls for that account use those temporary credentials. Nothing long-lived is stored.
  5. Grant each role only the permissions the portal needs (least privilege). Read-only roles are fine for inventory and validation.
Trust policy in the target account (who may assume the role)
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "AWS": "arn:aws:iam::<HUB_ACCOUNT_ID>:role/FDENexusPortal" },
    "Action": "sts:AssumeRole",
    "Condition": { "StringEquals": { "sts:ExternalId": "fde-nexus" } }
  }]
}
Permissions the hub role needs (to assume target roles)
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "sts:AssumeRole",
    "Resource": "arn:aws:iam::*:role/FDENexusCrossAccountRole"
  }]
}

Demo only. These policies are examples. No real STS call is made from this static UI.
